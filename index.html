One project, two runtime generations

The repository preserves two generations of the common PV-PP runtime. Runtime V1 remains unchanged for reproducibility, compatibility, and historical reference. Runtime V2 is a controlled successor developed from the mature V1 codebase and incorporates the Version 2 framework interfaces and subsequent runtime architecture.

P_I(t) → Φ → H → G → R → Graph/seed substrate → Π → Π completeness → Joint Recovery → Constraints → Domain Framing → Adequacy → Σ → ε
Framework meaning remains governed by the authoritative PV-PP framework documentation. The runtime packages implement the corresponding application interfaces; runtime code does not redefine the theory.

Host/runtime boundary

The runtime owns

  • the common PV-PP decision and governance architecture;
  • registered and governed represented structure;
  • canonical candidate evaluation, adequacy, and Σ selection;
  • execution licensing and ε authority boundaries; and
  • governed invalidation and re-entry mechanisms.

The host/application owns

  • authoritative actual state and world mechanics;
  • application-specific semantics and measurements;
  • external persistence and enforcement mechanisms;
  • neutral causal/world projections supplied through runtime boundaries; and
  • the authoritative Layer-1 state transition.

Runtime selection or licensing does not itself mutate the authoritative external world.

Runtime V2 highlights

Runtime V2 extends the original runtime with earliest-invalidated-stage governance re-entry, provenance-bearing dynamic Graph and structural governance, evidence-source and control-topology handling, non-scalar capability evolution and constructibility, and cross-domain architecture-invariance instrumentation.

v0.131 also requires native consequential invocation through the PV-PP interface to derive from runtime-private provenance across the canonical decision cycle → Σ → execution license → active ε episode → native authorization → invocation lineage. Host-created or reconstructed authority-looking objects do not create PV-PP native execution authority.

Asynchronous/distributed execution, autonomous semantic discovery, automatic PP-domain invention, unrestricted self-modification, and replacement of conventional operating-system/IAM/network enforcement remain outside the current runtime scope.

Repository organization

The two runtime generations are kept side by side in the same repository:

PV-PP-Runtime-API/  ├── runtime-v1/   └── v0.70 frozen generation    └── runtime-v2/      └── v0.131 successor generation

Development builds between the two freezes are engineering history rather than separate supported runtime generations. Runtime-specific README files, tests, examples, benchmarks, and documentation remain with their respective generation.

About PV-PP

Productive Value–Productive Power (PV-PP) is an economic and decision framework centered on Productive Value, Productive Power, represented and perceived productive state, governing domains, recovery structure, and viability-aware action selection.

This site concerns the runtime API specifically. It does not reproduce the complete theoretical, mathematical, benchmark, proof, or research record of the PV-PP framework.
